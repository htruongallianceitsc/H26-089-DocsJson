# Project Blueprint – Level 3 Detailed Specifications

## Compatibility commitment

`project-specification.schema.json` is generated by expanding the *actual Level 2 schema*. It **does not remove or change any existing fields, allowed values or required keys**. New fields and catalogs are optional. `meta.schemaVersion` remains `"1.0"` because the inherited schema fixes that value; it describes the base contract, not the detail level. Use `$schema` to select validation level. Existing Level 1 / Level 2 JSON may validate against Level 3 without adding new keys.

Caution: JSON already enhanced to Level 3 **will not validate under the old strict Level 1/2 schemas** (`additionalProperties: false`). Backward compatibility here means old data works with new schema, not vice versa.

## Files

- `project-overview.schema.json` + example: unchanged Level 1
- `project-architecture.schema.json` + example: unchanged Level 2
- `project-specification.schema.json` + example: Level 3
- `validate_references.py`: original Level 2 validator
- `validate_references_level3.py`: validates L1, L2, L3 against L3 schema and checks graph links
- `test_compatibility.py`: regression and negative tests

## Added optional Level 3 components

- `requirements` (`R-*`): title, description, priority, feature, linked AC/rules
- `acceptanceCriteria` (`AC-*`): Given/When/Then, requirements, linked tests
- `flows` (`FL-*`): ordered steps with screen/API references and `next` step IDs
- `testCases` (`TC-*`): test steps, expected result, links and execution status
- `databaseSpecs` (`DB-*`): table, indexes, keys and constraints
- `apis.*.contract`: auth, request/response/error details
- `screens.*.spec`: fields, actions, states, design reference
- `features.*`: optional links to new L3 catalogs and doc paths
- `entities.*.fields.*`: optional constraints/enums/precision/index metadata
- `businessRules.*.details`: optional condition, effect, exceptions

Example is illustrative specification only, not verified implementation or actual test outcome. Optional `payload.schema` supports embedded JSON Schema fragments without formal `$ref` resolution into an external OpenAPI document.

## Commands

```bash
python -m pip install jsonschema
python validate_references_level3.py project-overview.example.json
python validate_references_level3.py project-architecture.example.json
python validate_references_level3.py project-specification.example.json
python test_compatibility.py
```

## Upgrade path

1. Retain `meta`, all original feature IDs and their existing properties.
2. Point `$schema` to `./project-specification.schema.json` only when adopting L3.
3. Add one optional new catalog at a time and connect via ID arrays.
4. Run schema + cross-reference validator. Review inferred facts manually when generated by AI.

**Note:** A portable unified catalog using external docs, source evidence, and cross-file references can be introduced in a future version; this level deliberately remains one lightweight JSON file.
